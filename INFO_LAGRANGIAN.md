# T3 UV Lagrangian and Matching

This file documents the UV-model and EFT-matching side of the T3 neutrino-mass pipeline.  `INFO_PIPELINE.md` gives the complete repository flow and `INFO_RGE.md` covers the running and low-energy stages.

## 1. T3 representations and hypercharge

The code uses

$$
Q=T_3+Y.
$$

For the Restrepo-Zapata-Yaguna T3 classification parameter $\alpha$, the project's physical hypercharges are

$$
Y(S_1)=\frac{\alpha}{2},\qquad
Y(S_2)=\frac{\alpha+2}{2},\qquad
Y(F)=\frac{\alpha+1}{2}.
$$

The classification paper writes the doubled quantity $Y_{\rm RZY}=2Y$, corresponding to the convention $Q=T_3+Y_{\rm RZY}/2$.

The historical classes are

| class | $d_{S_1}$ | $d_{S_2}$ | $d_F$ |
|---|---:|---:|---:|
| T3-A | 1 | 3 | 2 |
| T3-B | 2 | 2 | 1 |
| T3-C | 2 | 2 | 3 |
| T3-D | 3 | 1 | 2 |
| T3-E | 3 | 3 | 2 |

The topology conditions require each scalar to lie in the product generated by the lepton doublet and the heavy fermion,

$$
d_{S_i}=d_F\pm1,
$$

and the two scalar roles must support the triplet contraction required by the Higgs pair.

Normal production mode currently supports SU(2) dimensions up to 3.  `--force` can attempt a larger topology-compatible representation but does not guarantee support from the downstream RGE implementation.

Normal mode also requires at least one electrically neutral BSM component.  `--force` can bypass that phenomenological restriction while still enforcing the T3 topology.

## 2. Physical versus formal scalar roles

The generic topology is written with the formal fields

```text
S1, S2, F
```

but the shared-scalar/scotogenic branch contains one physical scalar `S` and the heavy fermion `F`.

`common/T3Fields.py` is the authoritative Python definition of this distinction.  Threshold planning uses physical fields.  Only the Wolfram matching boundary expands the physical shared scalar back to both formal roles `S1,S2`.

For the T3-B point $\alpha=-1$,

$$
(d_{S_1},d_{S_2},d_F)=(2,2,1),
$$

with

$$
Y(S_1)=-\frac12,\quad Y(S_2)=+\frac12,\quad Y(F)=0.
$$

The two formal scalar doublets can therefore represent one physical doublet and its conjugate, reproducing the scotogenic field content.

## 3. UV interaction content

The T3 neutrino-mass topology requires two Yukawa vertices and one scalar mixing interaction.  Schematically,

$$
\mathcal L_{\rm T3}
\supset
 y_1 LFS_1
+y_2 LFS_2
+\lambda_{T3}HHS_1S_2^\dagger
+\text{h.c.}
$$

The actual field conjugations, chiral structures, and SU(2) invariant tensors are representation dependent and are constructed by the Wolfram model builder.  The schematic expression should therefore not be read as a literal field ordering for every class.

The internal coupling name `lambdaT3` is kept generic.  It can be identified with the usual scotogenic $\lambda_5$ only after the shared-scalar/conjugation convention is fixed for that limit; report notation may display the corresponding scotogenic symbol without globally changing the internal generic coupling.

## 4. Python model-selection boundary

The refactored Python orchestration separates selecting a model from constructing it.

`model/T3Study.py` creates `T3ModelRequest` objects for:

- smoke benchmarks;
- hypercharge scans;
- representation/dimension scans;
- direct ordinary `--dims DS1 DS2 DF` requests;
- shared-scalar `--dims DS DF` requests.

`Lagrangian/T3ModelMatching.py` then sends each selected request to the existing verified entry points in `Lagrangian/Runner.py`.

This separation is architectural only; it does not reimplement the matching formula.

## 5. Runner validation

`Lagrangian/Runner.py` checks the requested representation before launching Wolfram.

The distinction is:

1. **T3 topology validity** — always required;
2. **current production representation support** — can be bypassed with `--force`;
3. **neutral-component requirement** — can be bypassed with `--force`.

`--force` therefore does not turn an arbitrary representation assignment into a T3 model.

The runner also converts the physical threshold plan to the formal Wolfram roles.  In shared-scalar mode, a physical threshold containing `S` expands to both formal roles `S1,S2` for the generic T3 matching code.

## 6. Wolfram model construction

The principal model-building files are:

```text
Lagrangian/model/T3ModelCatalog.wl
Lagrangian/model/T3Fields.wl
Lagrangian/model/SU2Invariants.wl
Lagrangian/model/LagrangianBuilder.wl
Lagrangian/interactions/T3Topology.wl
Lagrangian/interactions/ScalarPotential.wl
```

Their roles are:

- define the representation data and alpha-dependent hypercharges;
- define BSM fields and couplings;
- obtain Matchete invariant tensors/Clebsch-Gordan structures;
- construct gauge-invariant candidate interactions;
- retain the interactions needed for the T3 topology;
- construct the scalar potential used by matching and running.

Candidate terms and the completed Lagrangian are checked with the existing Matchete validation machinery before the model is accepted.

## 7. One-loop matching

The default production target is

$$
d_{\rm EFT}=5,\qquad L=1.
$$

The existing Matchete matching flow is conceptually

```text
UV Lagrangian
    -> Match
    -> GreensSimplify
    -> EOMSimplify
    -> EvaluateLoopFunctions
    -> ReplaceEffectiveCouplings
    -> matched EFT
```

A Standard-Model-only calculation is also performed and subtracted so that the saved BSM EFT contribution is

$$
\mathcal L_{\rm EFT}^{\rm BSM}
=
\mathcal L_{\rm EFT}^{\rm full}
-
\mathcal L_{\rm EFT}^{\rm SM}.
$$

## 8. Weinberg-operator extraction

The dimension-five matched result is searched for the Weinberg operator and its Hermitian conjugate.  The project records the chosen holomorphic orientation once rather than double-counting the conjugate term.

The resulting coefficient is the input to the downstream RGE pipeline.  After all heavy thresholds have been treated, the physical coefficient is related to the Majorana mass by

$$
m_\nu=-\frac{v_{246}^2}{2}C_5.
$$

The scotogenic normalization used by the modern literature must be handled consistently with the real-scalar/complex-scalar normalization; the repository retains regression tests for this convention rather than silently modifying the one-loop factor during refactoring.

## 9. Sequential thresholds

`PipelinePlan` can describe any ordered partition of the physical heavy fields.  `Lagrangian/RunThresholdStage.wl` performs the sequential matching calculations requested by the plan.

The currently verified hierarchical production path is fermion first, followed by all remaining physical scalars at a common lower threshold:

```text
ordinary: F -> (S1,S2)
shared:   F -> S
```

A common threshold, with all heavy fields removed together, is also supported and requires no nontrivial heavy-field running interval.

### Scalar-first scope

A scalar-first threshold can generate an intermediate dimension-six operator, schematically

$$
\frac{y\lambda_{T3}}{M_S^2}LFHHS,
$$

which can later feed the leading Weinberg operator. It is therefore not consistent to represent scalar-first matching by simply truncating the intermediate theory at $d\le5$.

For the present honours-project production calculation, scalar-first and partially split scalar hierarchies are not executed. The supported matching choices are the common threshold and the verified fermion-first sequence `F -> (S1,S2)` (or `F -> S` in shared-scalar mode). The CLI rejects unsupported threshold orders before Wolfram/Matchete is launched.

## 10. Data passed to the RGE layer

The matching stage exports the information needed downstream, including:

- matched EFT expressions;
- extracted Weinberg coefficient;
- threshold-stage summaries;
- scalar and fermion representation metadata;
- CG/invariant-tensor information needed by the tensor RGE adapters;
- tree-level intermediate Wilson seeds when a sequential fermion-first threshold is used.

The Python `RunRecord` and `EFTStageRecord` classes contain metadata and paths only; they do not perform the physics calculation themselves.

## 11. Practical execution

Ordinary T3 example:

```powershell
python pipeline.py --dims 2 2 1 --alpha -1
```

Shared-scalar/scotogenic example:

```powershell
python pipeline.py --dims 2 1
```

Verified hierarchical fermion-first example:

```powershell
python pipeline.py --dims 2 2 1 --alpha -1 `
    --threshold F `
    --threshold S1 S2
```

After modifying the Lagrangian/matching layer, run the Python suite and then an actual Wolfram/Matchete smoke calculation:

```powershell
python -m pytest -q
python pipeline.py --smoke
```
