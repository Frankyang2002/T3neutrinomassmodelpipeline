## Installation and full local execution (PowerShell)

```powershell
cd C:\thesistemp\T3neutrinomassmodelpipeline
$zip = "$HOME\Downloads\T3FullCompletionStack_Local.zip"
Expand-Archive -LiteralPath $zip -DestinationPath . -Force

python scripts\RunT3CompletionBatch.py --self-test
python scripts\TestT3CompletionStackSynthetic.py

# Uses your existing 16 *actual* Wolfram RGBeta exports.
# Includes an RHS preflight for every model, then integrates all couplings.
python scripts\RunT3CompletionBatch.py --all
$LASTEXITCODE
```

The `--all` command is the complete run; it performs the RHS preflight internally, including the rephasing diagnostic, before numerical integration. To evaluate each full native RHS without integrating, use `--preflight`. To focus on the six new-Yukawa models, use `--six`. To run A(0) only, use `--model A_p0`. If plotting is unavailable or you prefer data only, add `--no-plots`.

If the production model source changed since the 16 RGBeta reports were generated, the integrity check will stop intentionally; regenerate with `python scripts\RunT3ExtraYukawaStack.py --all` first. There is no Wolfram execution in this ZIP's numerical batch: it consumes the successful Wolfram exports already generated by your local machine.

## What exactly is implemented

Each model's entire exported `report_betas` dictionary is evolved together in t = ln(mu) with

\[
\frac{d X}{dt} = \frac{\beta_X^{(1)}}{16\pi^2}.
\]

This includes SM gauge and Yukawa couplings, both standard T3 Yukawas, `MF`, scalar masses, all old and *generated general-scalar quartics*, and `y1Conj`/`y2Conj` when permitted. There is no silently dropped beta key. New generated quartics default to zero at the UV reference, **but are dynamical and can be radiatively sourced**. The initial extra Yukawa is `0.3 * max(max|y1|, max|y2|, 1e-6)` times a fixed non-diagonal complex test matrix. The control uses exactly the same full beta system with that extra matrix initially zero; the control is not falsely assumed to stay zero. The endpoint is above the *evolved* heavy mass and the reference heavy threshold.

The new numerical state is intentionally separate from the production `T3UVState` and existing threshold/Weinberg runner. Its inputs use historical fitted-reference **numerical values as illustrative RGBeta coordinates**, NOT as a certified physical Matchete-to-RGBeta map.

## What is NOT physically certified or performed

**This package does not establish the absolute physical cross-package coupling dictionary** for the heavy fermion, both standard Yukawas, independent extra Yukawas, triplet basis and all scalar couplings. The previous A(0) spinor test fixed eta only under an explicit Weyl-basis choice. Therefore this package **does not inject unconverted extra Yukawas into Matchete C5 matching, does not integrate through fermion/scalar EFT thresholds, and does not claim extended neutrino masses or oscillation fits**. The JSON physical readiness gate records these blockers separately from verified RGBeta UV results.

Real 16-model integration **must be run locally**. The exact ODE and 16-model synthetic test passed in this build environment, but the user's actual 16 RGBeta exported expressions and physical matching cannot be tested in this environment.
