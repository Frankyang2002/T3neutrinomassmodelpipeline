# Numerical pipeline, fitting and validation

Based on `INFO_NUMERICAL.md`, `INFO_IMPLEMENTATION.md`, `INFO_TESTS.md`, the benchmark-selection note, and the documented commands from the older README files. This is a concise operational map, not a line-by-line replacement of the old numerical implementation register.

## 1. Layer separation

```text
Numerical/core/           state, vector encoding, beta evaluation
Numerical/running/        UV -> F threshold -> EFT1 -> scalar threshold -> Weinberg EFT
Numerical/fitting/        parameter search, chi2, optimisation, sensitivity
Numerical/diagnostics/    saved trajectories, physical intermediate diagnostics
Numerical/plotting/       presentation from stored diagnostics
Numerical/orchestration/  CLI studies and persistence
```

Representative files: `core/State.py`, `core/StateVector.py`, `core/RGBetaEvaluator.py`, `core/BetaVector.py`; `running/UVRunner.py`, `FermionThresholdBoundary.py`, `IntermediateScalarRunner.py`, `ScalarThresholdBoundary.py`, `SMWeinbergEvolution.py`; `fitting/OscillationFit.py`, `ParameterScan.py`, `OscillationOptimizer.py`; `plotting/BuildDisplayResults.py`; `orchestration/PipelineNumericalResults.py`.

`RGE/matching/` owns final matching formulae. `Numerical/` consumes exported expressions and evaluates them. `physics/` interprets the resulting \(C_5\) in terms of neutrino masses and PMNS observables.

## 2. Numerical method and normalisations

The documented convention is \(t=\ln\mu\), with beta-function numerators converted to \(dX/dt\) by exactly one factor \((16\pi^2)^{-1}\). Complex fields and matrices are encoded into real solver vectors. Fixed reference configurations record tolerances including `rtol=1e-8`, `atol=1e-11` and 120 stored scale points; those are choices, not convergence proofs. The matched Majorana flavour coefficient is numerically symmetrised before Takagi decomposition.

The code uses a custom Takagi factorisation and explicit ordering/phase choices. Its residual and matrix-symmetry controls must be included in any numerical validation. Fitted low-energy observables depend on the charged-lepton basis transformation; this must remain consistent between ablations.

## 3. Fixed scenarios versus fitted benchmarks

The four fixed scenarios are the combinations of:

- `smallY`/`largeY`: nominal \(Y=0.005\) or 0.5;
- `smallL`/`largeL`: \(\lambda_{T3}^{\rm ref}=0.1\) or 1.0.

For Class E, the benchmark-only initialisation scales the lambda reference by 1/2; see `PHYSICS.md`. The original full grid comprises 16 models × four scenarios = 64 cases. A completed integration is not a successful neutrino-oscillation fit.

The NuFIT-targeted feasibility workflow reuses saved RGBeta and matching artifacts, calibrates an overall Yukawa scale, varies entries of two 3x3 Yukawa matrices and optionally performs local refinement. The source note describes a pilot using 15 logarithmic calibration factors, 256 Sobol trials in 18 real Yukawa entries, and local least-squares refinement. It is *not* a fit to four strictly separated small/large coupling regimes unless those parameter bounds are enforced.

Frozen fitted reference inputs and provenance are under `Numerical/benchmarks/fitted_reference/`, including `benchmark_manifest.json`; use the saved per-model matrices instead of assuming that each fitted candidate has the nominal fixed-grid Yukawas.

## 4. Reproducible commands (PowerShell)

Run from the repository root in the configured environment:

```powershell
python pipeline.py --help
python -m pytest -q
python -m pytest -q tests/test_extract_full_comparison_results.py
python -m Numerical.diagnostics.ExtractFullComparisonResults
python -m Numerical.plotting.BuildDisplayResults --output Reports/output/display
python -m Numerical.orchestration.RunFittedSensitivityComparison --help
```

The fitted-sensitivity runner can reuse existing `output/full/comparison/smallY_smallL` exports and the locally saved fit directories. Its initial dry-run/`--run` behaviour should be checked using `--help` before launching a large scan. A full `python pipeline.py --full` can invoke symbolic external dependencies; use it only for a deliberate end-to-end run.

An example historical display workflow is:

```powershell
python -m Numerical.plotting.BuildFittedModelEnvelopes --scenario smallY_smallL --output Reports/output/display/fitted_model_envelopes_all.html
```

Whether each historical plotting script/flag remains present is determined by current local code; old README replacement instructions are not authoritative API contracts.

## 5. Saved results and output ownership

- Raw full comparison diagnostics: `output/full/comparison/` and per-model `running_diagnostics.json`.
- Some study JSON/CSV: `Reports/output/full/` (for example `staged_rg_comparison/smallY_smallL/scan.json`).
- Rebuildable presentations: `Reports/output/display*/` and PNG/HTML generated by plotting/report scripts.
- NuFIT targets: `configs/nufit_6_1_ic24_no.json`.
- Frozen fitted inputs: `Numerical/benchmarks/fitted_reference/`.

Be careful with automatically saved/overwritten configurations. As documented in the implementation notes, a run with `--reset-numerical-configs` is not equivalent to a resumed run that reuses frozen/local parameters. Preserve the exact input JSON and provenance hashes when comparing results.

## 6. Testing strategy

1. **Algebra/state contracts:** one-loop beta-vector mapping, complex packing, dimensions, threshold orientation, group-factor and Weinberg coefficient conventions.
2. **Numerical contracts:** ODE evolution, saved diagnostics, Takagi/observables, fit objective, sensitivity scaling, stored outputs.
3. **Architecture contracts:** production matching expression ownership, selection of input rather than stale resolved configurations, standard display regeneration.
4. **External independent validation:** RGBeta/Matchete exports and Wolfram checks; a Python-only test pass is not equivalent to a fresh successful symbolic regression.

The complete file-by-file test map remains in `INFO_TESTS.md` until every test path has been checked for current relevance. Representative quick checks:

```powershell
python -m pytest -q tests/test_t3_multiplicity_benchmark.py
python -m pytest -q tests/test_full_study_architecture.py
python -m pytest -q
```

## 7. Recorded reproducibility issues

Archived incident notes document (i) threshold ordering producing no intermediate EFT artifacts if a non-fermion-first/default threshold mode is used, and (ii) `resolved` input configurations unintentionally overwriting scenario distinctions. The corrected scenario logic should prioritise `configs/generated_model_sets/comparison/<scenario>/input/` for fixed-grid studies, and completed runs should retain their configuration fingerprint. The incident notes are useful historical checks; they are not new physics results.
