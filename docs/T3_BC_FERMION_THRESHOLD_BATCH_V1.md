# B/C UV -> EFT1 fermion threshold batch v1

This batch is a *source-verified handoff*, not a new physical finite matching calculation. The repository already implements native Matchete tree LLSS matching and raw one-loop LLHH extraction in `RunGeneralT3FermionFirstEFT1Tree.py`, `RunGeneralT3FermionFirstEFT1OneLoop.py`, and `BuildT3BCFHardBoundaryInterface.experimental.py`.

Run `scripts/RunT3BCFermionThresholdBatch.ps1` from repo root. It validates native reports and original matching artifacts, reruns the existing source F-hard term parser, and records exact symbolic 2x2 polynomial sectors for both models. The F-hard source expects 68 pole, 68 mass-log and 68 constant terms, with pole/log equality. F-hard finite constants are **formal**, not a renormalized Wilson boundary. The EFT1 field content is the SM plus two scalar doublets (mass eigenstates X/Y), with F integrated out. The original native output is not modified.

Expected upstream prerequisites (already generated by earlier pipeline): `output/general_t3_mass_eigen_matchete/eft1_fermion_first_tree/`, `output/general_t3_mass_eigen_matchete/eft1_fermion_first_oneloop/`, and the v11/v12 finite-interface provenance reports under `output/audits/`. If any is missing, run the repository's existing native source stages first; the batch fails closed instead of fabricating a coefficient. No EFT2 is created.

Outputs: `output/studies/t3_bc_fermion_threshold_batch_v1/summary.json`, `f_hard_formal_source.json`, `f_hard_extraction.log`.

Remaining physics blockers are UV/IR pole assignment, UV/EFT1 counterterms, inter-package coupling dictionary and finite field/EOM shifts. Do not add the formal F-hard constant to Y scalar matching and call it physical C5. Production sources remain unchanged.
