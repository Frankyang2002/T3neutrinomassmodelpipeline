# Reduced scalar zero-boundary Sobol campaign (new, separate from bulk48_v1)

## Physics scope

This is a **new numerical campaign**, not a reclassification of the previous 48-study results. Follow the saved Batch 1–8 relevance proof in `docs/T3_REDUCED_SCALAR_POTENTIAL_CONCLUSION.md`. The retained potential is

\[
V_{\rm red}=V_{\rm SM}+m_1^2S_1^\dagger S_1+m_2^2S_2^\dagger S_2
+V_{\rm ordinary\ self/portal}
+[\lambda_{T3} HH S_1S_2^\dagger+\mathrm{h.c.}].
\]

All 50 additional scalar quartic *model-slots* and 8 additional quadratic *model-slots* have **exact zero input coefficients**. This is **not a protecting symmetry**. The input scale is `1e5 GeV` for UV-frozen cases and `1e7 GeV` for UV-running cases. The B/C(-1) six already-represented additional quartics are actively zeroed in the in-memory UV state. All model-specific newly represented additional quartics are complex zero sidecars. The solver **does evolve** extra quartics that are radiatively generated by native one-loop RGBeta UV/EFT1 equations. It does **not evolve** the 8 additional quadratic terms: the saved one-loop zero-boundary relevance proof found no generation in its separately audited iterated source chains, subject to its stated matching and higher-loop limitations.

The one-loop neutrino mass uses existing Stage36 model-specific hard+direct (12 models) or explicitly *legacy one-scale* (4 extreme-hypercharge models) C5. It does **not** insert radiatively generated B/C extra quartics into C5: with zero UV boundary their direct one-loop C5 insertion is formally a higher fixed-loop order. Likewise, no complete fermion-first LLSS/C12 Wilson transfer or physical Matchete/RGBeta map is certified. This is a **fixed-order leading-one-loop C5 evaluation on one-loop-RG-improved scalar backgrounds**, not a fully consistent NLO prediction or the general scalar potential. Vacuum boundedness and numerical C5 error bars are not certified.

## Comparisons

Three scenario keys:

| Key | A–D topology lambda | E topology lambda | Input scale | UV RGEs |
|---|---:|---:|---:|---|
| `small_uv_frozen_5e-9` | `5e-9` | `2.5e-9` | `1e5 GeV` | disabled |
| `large_uv_frozen_0p5` | `0.5` | `0.25` | `1e5 GeV` | disabled |
| `small_uv_running_5e-9` | `5e-9` | `2.5e-9` | `1e7 GeV` | enabled |

For each model and scenario:

1. Verify the exact original fitted seed configuration and matched model identity, source hashes, beta symbol inventories and target.
2. Evaluate 1 original seed + N scrambled Sobol Yukawa trial points (18 real parameters, constrained search window).
3. Pick the best `--starts` genuinely mass-safe/neutrino-evaluable trials and **always** apply bounded `least_squares` (`--max-nfev` per local start), including when the old seed already passes χ² ≤ 5.86. No local optimiser is attempted if the Sobol/seed set has no mass-safe point. The finite-difference Jacobian can require many more physics evaluations than `max_nfev`.
4. Independently evaluate the same scenario's fixed A(-2) Yukawa matrices at the *target model's* representation, scalar boundary, and matching artifact. By default these A(-2) matrices come from the original historical study, **not** from the current reduced refit; the source is reported. Option `--a2-source new-fit` uses a newly accepted A(-2) fit from this same campaign and fails closed for the comparison if that fit is unavailable; A(-2) must be selected.
5. Save the complete individual best fit, five observables, shared point evaluation, rejection reasons, exact solver evaluation counts and source digests. A screened-out trial has **no χ²**; it must not be labelled a poor fit.

The source `fit.json` reports the fitted Yukawa vector. Its `fitted_config.json` alone does **not** encode extra zero sidecar evolution. The new runner must be used for replay, not an old production command that ignores it.

## Installation

Unzip the single ZIP preserving its relative paths under `C:\thesistemp\T3neutrinomassmodelpipeline`. It adds these files without replacing existing production files:

- `scripts/RunT3ReducedScalarSobolComparison.py`
- `tests/python/test_t3_reduced_scalar_sobol_comparison.py`
- `docs/T3_REDUCED_SCALAR_SOBOL_COMPARISON.md`

Existing inputs are **read-only**; all output goes under `output/studies/reduced_scalar_sobol/<run-id>/`.

```powershell
cd C:\thesistemp\T3neutrinomassmodelpipeline
Expand-Archive -LiteralPath 'C:\path\to\T3_ReducedScalar_Sobol_Comparison.zip' -DestinationPath . -Force
python -m pytest -q tests\python\test_t3_reduced_scalar_sobol_comparison.py

# Small first pilot: test both A(-2) and the special B(-1) source and zero boundary.
python -u -m scripts.RunT3ReducedScalarSobolComparison `
  --run-id reduced_pilot_v1 --models 'A_-2,B_-1' `
  --cases 'small_uv_frozen_5e-9' --sobol-points 8 --starts 1 --max-nfev 20

# After the pilot succeeds: separate 16 x 3 campaign, no overwrite.
python -u -m scripts.RunT3ReducedScalarSobolComparison `
  --run-id reduced_48_v1 --sobol-points 32 --starts 2 --max-nfev 60

# Safe continuation after interruption (same settings/selection required).
python -u -m scripts.RunT3ReducedScalarSobolComparison `
  --run-id reduced_48_v1 --sobol-points 32 --starts 2 --max-nfev 60 --resume

Import-Csv .\output\studies\reduced_scalar_sobol\reduced_48_v1\comparison.csv |
  Format-Table model,case,status,chi2_optimised,chi2_shared_a2 -AutoSize
```

A local `wolframscript` and RGBeta are required **only if** validated native EFT1 beta exports have not already been saved, notably B/C(-1). The source code contains no automatic fallback to missing beta systems or a fabricated χ². A failed cell writes `FailedOrUnavailable` with a traceback, without a neutrino result.

**Frozen physical-study data and previous outputs are never modified**, including `bulk48_v1`. If retrying a failed case, create a new run ID or explicitly inspect the error; `--resume` intentionally reuses its written record unchanged.

## Overnight frozen-UV refinement (v2 runner, October 2026)

This **full replacement** runner supports two opt-in numerical refinements:

- `--warm-start-run ID`: reuses each model's **already accepted** Yukawa vector
  from a preceding reduced-scalar campaign as a separately evaluated initial
  point. The model/scenario, accepted status, all 18 Yukawa coefficients,
  finiteness and absolute perturbativity box are verified, and the prior
  `fit.json` SHA-256 is recorded. The other model parameters are **not** copied.
- `--a2-as-start`: inserts the **current scenario's newly accepted A(-2)**
  Yukawa point into each other model's **individual** candidate search. It
  requires `--a2-source new-fit`. This is important when the direct shared
  A(-2) evaluation fits better than a previous individual optimiser result.
  The reference is still evaluated separately for the comparison column.
  Both extra points can enlarge the local Yukawa search box within the original
  absolute `sqrt(4*pi)` cap. They do **not** change any scalar boundary,
  physical screen, matching source or target.

The output includes `extra_trial_labels` and
`extra_optimisation_seed_sources`, and unchanged `sobol_trials`/
`optimiser_starts` audit data. Warm inputs and prior results are never
modified. The new run ID must differ from the warm-source run ID.

In PowerShell (single-line commands avoid the PSReadLine rendering issue):

```powershell
cd C:\thesistemp\T3neutrinomassmodelpipeline
Expand-Archive -LiteralPath 'C:\path\to\T3_ReducedScalar_Overnight_Refinement.zip' -DestinationPath . -Force
python -m pytest -q tests\python\test_t3_reduced_scalar_sobol_comparison.py
python -u -m scripts.RunT3ReducedScalarSobolComparison --run-id reduced_frozen_overnight_v2 --cases "small_uv_frozen_5e-9,large_uv_frozen_0p5" --a2-source new-fit --a2-as-start --warm-start-run reduced_frozen_a2_newfit_v1 --sobol-points 64 --starts 3 --max-nfev 80 2>&1 | Tee-Object -FilePath overnight_refinement.log
```

Inspect `output/studies/reduced_scalar_sobol/reduced_frozen_overnight_v2/summary.md`
when complete. For interruption, rerun exactly the same command with
`--resume` before `2>&1`; the runner checks the saved settings and skips
complete case files. **Do not change seed counts or other flags on resume.**

Runtime is not benchmarked. Due to 18-variable finite-difference Jacobians,
`max-nfev` is **not** a strict bound on calls to the full physics evaluator.
This is deliberately a substantial overnight refinement, but may take longer
than one night depending on CPU and model costs. It does not address the
separate UV-running scalar-mass problem, which requires a new boundary study.
